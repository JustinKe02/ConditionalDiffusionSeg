# 50 GiB数据盘：实验存储预算与防满盘方案

## 1. 当前实测与结论

2026-10-17检查：/root/autodl-tmp总50.00 GiB，已用约11.26 GiB，剩38.74 GiB（GiB按1024³字节）。主要现有目录约：conda 8.37 GiB、PLNetV2 1.62 GiB、PhysicalNet 1.26 GiB。未删除或改动这些项目与环境。

现有余量能容纳下面的受控实验方案，但不能无限保存每轮checkpoint、浮点概率图或扩散轨迹。预算不是实测训练占用；下表为实现前的保守情景估算；现已实现网络，实测参数量见末尾补充，完整尺寸checkpoint及日志增长仍需在P0校准。

## 2. 单次实验预算

设模型参数数量P，FP32权重约4P字节。保存策略明确为：

- best：只保存最佳模型权重、模型配置与必要元数据，约4P字节；用于评估，不能独立恢复optimizer。
- last：保存模型、AdamW两个动量、scheduler、RNG、epoch/global_step等完整恢复状态，主体约12P字节。
- 常驻两份合计主体约16P字节。序列化头、buffer和其他状态不包含在这个近似公式中，需实测。
- 使用同目录临时文件与原子替换，替换last时短暂额外占约12P；逐个写入，不同时生成多个临时checkpoint。空间不足时不能先删掉唯一last来冒险保存。
- 不保存每轮历史版本或里程碑；重复最佳模型更新替换原best。所有其他实验与用户数据不做自动清理。

| 项目 | 每run预算/策略 |
|---|---|
| checkpoint | 按16P估算，另外预留原子写入临时空间 |
| TensorBoard | 256 MiB；每次验证4个固定样本、4种面板，预览最长边512 |
| 原分辨率预测 | 256 MiB；uint8类别PNG，仅一套最佳val结果及一套最终test结果 |
| CSV/JSON/元数据 | 32 MiB |
| P0调试、报告图表、额外元数据等 | 全项目另预留2 GiB |

四种面板全部按RGB、512×385、4样本、20次验证估算，未压缩像素约180.5 MiB；256 MiB是日志预算，不是TensorBoard自动限额。实际编码、事件开销、恢复备份等必须监测，超额需审查，不能假设压缩一定足够。

25张val+27张test的单通道uint8原始mask共约244 MiB；整数PNG通常有压缩收益，但仍按256 MiB预算。保留一套最佳val的含义是更新时替换本run已管理的上一套，不能每次改善就新建全量归档。临时替换空间计入共享预留并在实际写入前检查。测试只在最终协议冻结后执行。

## 3. 整套实验情景估算

规模取最大计划：3次预实验+18次正式训练+3次条件对照=24次。为保守起见，40轮预实验也按200轮日志预算计算。以下包含2 GiB共享预留，不包含现有11.26 GiB占用，也不包含额外重跑。

| 假设每模型参数量 | 每run约占 | 24次+共享预留 | 当前空间扣除后约剩 |
|---|---:|---:|---:|
| 500万 | 0.61 GiB | 16.54 GiB | 22.20 GiB |
| 1000万 | 0.68 GiB | 18.33 GiB | 20.41 GiB |
| 2000万 | 0.83 GiB | 21.90 GiB | 16.84 GiB |

表中参数数量为实现前预算情景，当前实际网络参数量见末尾补充。P3多步数/多次采样默认保存数值指标，复用checkpoint，不为每个设置复制权重或全套预测。额外可视化只输出固定少量样本并计入共享预算。额外重跑、更多对照、额外数据集必须重新预算。

目标为项目新增占用约20 GiB，上限26 GiB；单run超过1 GiB需要审查。剩余空间至少保留8 GiB，低于12 GiB告警。这些约束已接入首版训练器及评估脚本；只读检查脚本用于整套计划估算，运行期检查用于当前run。

## 4. 最容易写满磁盘的产物

原图2560×1922，四通道float32概率图单张约75.1 MiB：

- 25张val的一套概率图约1.83 GiB。
- 若保存20个扩散中间状态，单次全量val轨迹约36.66 GiB。
- 若每次验证保存全量概率图，20次验证也约36.66 GiB，尚未计其他文件。

因此默认不保存全量浮点概率图、全量扩散轨迹、逐轮模型归档或逐轮全量预测。只在CPU/GPU内存中处理当前图像并及时释放，落盘保存整数类别与累计指标。原始图片直接读取已有路径；不新建数据副本或每run复制conda环境。

## 5. 启动与运行中的检查

现有只读脚本：

```bash
python /root/autodl-tmp/ConditionalDiffusionSeg/scripts/check_storage.py
```

默认按未来24次、每模型2000万参数预算；输出实际磁盘容量、预计新增空间及是否满足8 GiB保留空间和26 GiB项目上限。参数数量可用--parameters替换，--runs填写尚未运行的次数。估算中的共享2 GiB再次完整计入，对续跑偏保守。返回0表示当前假设下预算通过，2表示空间预算未通过，不启动或清理任何实验。

运行期检查已接入；首轮校准仍需完成：

1. P0测实际参数量、best/last文件尺寸、一次验证日志增长，重新外推总量。
2. 启动队列前检查全部剩余计划预算；每轮、每次验证、每次checkpoint/批量导出前复查。
3. 写入前检查预计文件及原子替换的瞬时占用，写入后仍保留8 GiB；记录disk_free_gib/run_size_gib/project_size_gib。
4. 达到项目上限、run上限或最低余量时停止新工作并明确报告；保留最后成功的checkpoint。只有空间预算仍允许时才保存新恢复点，否则不尝试危险的大文件写入，报告可能损失的最近训练进度。
5. 不自动删除其他run、历史成果或其他项目。处理本run临时文件也需校验归属；恢复日志备份计入限额。

外部进程可能同时占用磁盘，因此不能承诺绝不满盘；需要持续检查及磁盘写入异常处理，不能只在开跑时查一次。

## 6. 运行内存与GPU显存

本次cgroup内存上限90 GiB、当前约1.35 GiB；GPU为RTX3090 24 GiB，检查时约1 MiB已用。50 GiB指磁盘容量，不是运行内存或显存。

实际测试发现512裁块/batch4/FP32的五步迭代模型OOM；已统一改为batch2，三种模型都通过一次合成数据训练步。非扩散5次迭代的训练计算图可能更占显存；扩散推理需关闭梯度并逐步覆盖中间状态。固定窗口批次并逐图聚合，不能把完整数据集所有采样轨迹驻留内存。若显存不足，在正式比较前统一调整配方并记录；磁盘预算通过不等于显存已通过。
